---
title: "Same-chain swaps"
description: "Swap supported crypto assets on one chain through a Core-generated instruction."
---

Both assets must be supported on the same chain. Use canonical asset objects
and `estimate_payment`.

<Steps>
  <Step title="Estimate">
    Confirm the source amount or source ceiling, destination amount, fees,
    chain, and expiry. The estimate is recipient-free; a pure swap uses the
    connection's bound wallet internally.
  </Step>
  <Step title="Create and continue">
    Create one durable payment, satisfy the active authorization policy, and
    request its current instruction.
  </Step>
  <Step title="Execute">
    Local stdio uses `execute_payment_instruction`; Core checks allowance and
    submits an exact token approval only when required. Hosted OAuth opens the
    returned `transaction_signing_url` for owner signing through Privy. Do not
    use a spending grant for a swap.
  </Step>
  <Step title="Track">
    For local execution, retry an ambiguous result with the same request ID.
    Poll `get_payment` until terminal on either surface.
  </Step>
</Steps>

Never construct calldata or select an arbitrary token contract or spender.
