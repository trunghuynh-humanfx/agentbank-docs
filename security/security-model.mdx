---
title: "Security model"
description: "Understand AgentBank credential, wallet, scope, instruction, and payment-state boundaries."
---

- Local browser authorization binds one installation to the user's account;
  hosted OAuth binds a durable remote connection.
- Scopes restrict the operations available to that installation.
- Privy supplies wallet infrastructure without exposing keys through MCP.
- Core pins the wallet and route for payment execution.
- Only a current Core-owned instruction can be executed.
- Exact token approval is submitted only when required.
- Stable request IDs protect against duplicate logical actions.
- Sensitive credentials and World ID proofs are omitted from tool results.
- Partner identity is intentionally hidden.
- `get_payment` is the durable source of truth.
- Local credentials stay in an OS-user-scoped vault under a stable
  `AGENTBANK_MCP_PROFILE`; hosted connections do not expose a local credential.
- Hosted spending grants are bounded Privy permissions and can fund only the
  current immutable crypto-deposit instruction within their enforced limits.

AgentBank does not take custody of the user's wallet funds. Payment and banking
partners may process funds while completing supported routes.
